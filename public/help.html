1. 绑定你的第一个平台账号

Algorithm DX 把各平台的做题记录汇总到这台电脑上，无需另行注册。你只需要有对应平台的账号；还没有的话，先去该平台注册。

  1. 打开「账号管理」，找到「添加平台账号」。
  2. 在「这个账号属于谁」中选择已有的「我」。只有列表中没有自己时，才选「添加一个人」，填写本地显示名称并勾选「标记为『我』」。以后添加自己的其他平台账号，也选择同一个人。
  3. 选择平台，填写平台用户名或用户 ID。不确定填什么时，查看下面的账号填写表。洛谷、码蹄集还需要登录 Cookie；普通 Codeforces 记录不需要。
  4. 点击「保存账号」。看到账号出现在「已绑定账号」中后，点击页面顶部的「同步最新数据」。如果页面已经显示正在获取，等它完成即可。
  5. 打开「AC 记录」查看已通过的题目，或打开「练习数据」查看提交统计。AC 指答案已通过平台评测。没有记录时，先查看账号的同步状态，按常见问题排查。

想查看题友的记录？为对方「添加一个人」，不要勾选「我」，再绑定对方的平台账号。同一位题友的多个账号归到同一个本地名称下。这里的关注只影响本机展示，不会通知对方；能读取哪些记录取决于平台的公开范围。

2. 平台用户名 / 用户 ID 填什么？

本地显示名称是你在这里起的名字，例如「我」「同学小王」；平台用户名 / 用户 ID是用来查找平台账号的标识。平台显示的昵称不一定是这个标识。

平台账号栏怎么填是否需要 Cookie
Codeforces（简称 CF）个人主页 /profile/ 后的用户名。公开记录不需要；群组比赛见单独设置。
AtCoder个人主页 /users/ 后的用户名。不需要。
LeetCode 国际站leetcode.com/u/ 后、下一个斜杠前的字符。不需要；只支持近期公开提交。
力扣中国站leetcode.cn/u/ 后、下一个斜杠前的字符。与国际站分别绑定。近期公开 AC 不需要；回补历史需要本人的 Cookie。
洛谷例如主页地址以 /user/123456 结尾，就填 123456。同步需要你自己的 Cookie。
牛客个人主页 /users/ 或竞赛主页 /profile/ 后的数字。不需要。
码蹄集绑定自己：填写 Cookie 后，账号栏可留空，也可填自己的昵称或主页链接。绑定他人：填数字 ID 或他人主页链接。需要你自己的 Cookie，详见码蹄集步骤。

除码蹄集外，账号栏只填写上表指定的那段字符，不要粘贴整个网址。不要填写密码或电子邮箱。表中的网址片段只是定位方法，请从你要绑定的个人主页复制实际内容。

3. 同步最新数据，还是回补历史？

  • 同步最新数据：获取最近的提交，适合日常使用。打开或刷新页面时也会尝试自动同步；短时间内重复打开可能沿用刚刚同步的结果。
  • 回补历史：获取更早的提交。在「账号管理」中找到对应账号的「回补历史」操作。记录很多时需要多轮，下一轮会接着已保存的进度读取。普通自动同步不会补齐历史。

两种操作都会把读取到的记录存到本机，不会替你向平台提交答案。同步失败或断网时，已有记录仍会保留。

各平台能同步到什么范围？

  • Codeforces、牛客：支持近期记录和历史回补。CF 群组比赛需要单独配置；牛客只含公开编程练习，不含选择题。
  • AtCoder：支持近期记录和历史回补，数据来自 AtCoder Problems 第三方镜像，可能延迟或缺失。
  • LeetCode 国际站：最多读取 20 条近期公开提交，不支持完整历史回补。
  • 力扣中国站：普通同步最多读取 20 条近期公开 AC。填写与绑定账号一致的本人 Cookie 后，可回补本人可见历史，包含失败提交。保存新 Cookie 后会自动尝试开始回补；尚未完成时可继续点击「回补历史」。
  • 洛谷、码蹄集：配置自己的 Cookie 后，可同步近期记录并回补当前登录账号有权查看的历史。

「同步成功」不代表全部历史已经补齐；「可见历史已回补」也只表示当前数据源可读取的记录已遍历完。统计以本机已经保存的数据为准，未获取到的记录不能当作没有做过。

同步状态怎么理解？
  • 「已保存 / 已绑定」：账号或登录配置已经保存，接着看同步结果。
  • 「待配置 / 跳过」：还缺登录信息等必要配置；按提示补齐后重新同步。
  • 「同步失败」：已尝试读取但未成功，查看具体原因；更新过期 Cookie 或恢复网络后再试。
  • 「成功，新增 0 条」：可能没有新提交，也可能本轮仍在收集历史题目列表。结合回补进度判断，不必重新绑定账号。

4. 记录一次练习，查看 B50 成绩

同步得到的是提交记录，通常不能直接知道你思考了多久。要计算练习成绩，还需要实际用时。DX Rating 和 B50 目前只为 Codeforces 题目计分。

现在准备做题：使用计时器

  1. 先绑定自己的 CF 账号，打开「DX Rating」，在页面顶部选择自己。
  2. 在「准备就绪，开始解题」区域填写题号，例如 2259:A，或粘贴 CF 题目链接。这道题不需要已有提交。
  3. 准备好题目和写代码的工具，选择本次练习类型，点击「开始计时」。如果是首次自己完成，选择「首次独立解题」；使用过提示、题解或 AI，就选择相应的辅助选项。
  4. 在 CF 用绑定的账号提交答案。通过后，应用会自动检查并保存用时；也可点击「已提交，立即检查」。结算后可在「练习历史」查看这次记录。

计时到这次练习开始后、同账号同题的首个 AC 提交时间为止，等待同步和判题的时间不计入。程序运行期间约每 30 秒检查一次。

刷新或关闭浏览器页面不会暂停计时。请保持本机启动窗口运行；程序关闭或断网时无法检查新提交，恢复后会重新核对。普通计时器最长记录 24 小时。「取消计时（不保存）」不会留下练习记录，想保留未完成的尝试时可以手动添加。

已经做完题：补录用时

  1. 先同步 AC 记录，再打开 「DX Rating → 用时补录」，找到要补录的题，点击「填写用时」。
  2. 填写实际用时、练习类型和结束时间。只有记得用时时才补录，不需要猜测或补齐全部历史；旧题可以在「查看范围」中选择「历史未计时」。
  3. 想记录重做或未完成的练习，可点击「手动添加做题记录」。未完成时选择「未完成 / 放弃」，用时填实际投入的时间。

填错了可以到「练习历史」点击「修改记录」。需要保留记录但取消计分时，在修改窗口勾选「作废此条记录」。选择「不再提醒」只会隐藏补录提醒，不会删除提交或成绩。

保存以后，去哪里看？

  • 练习历史：查看每一次尝试，包括重做、辅助解题和未完成的记录。
  • 全部成绩：查看每道题的最佳有效成绩，可以筛选、排序和导出。
  • Rating 总览：显示 B50，即旧题中得分最高的 35 道，加上当前系统年度新题中得分最高的 15 道。DX Rating 是这些单题得分的总和，详见评分规则。
「自动识别」能判断我有没有看题解吗？

不能。应用只根据本机已保存的记录判断：本次练习开始前已经 AC 过这道题，就建议「熟题重做」；没有足够记录时保留未知。是否首次独立完成、是否使用题解或 AI，需要你自己选择，手动选择优先。辅助解题、未完成和已作废记录会保留在历史中，但不计入 B50。

比赛中的自动用时是按相邻完成提交的间隔估算的，可能与实际思考时间不同；发现不准时请修改。

5. 不知道做哪道题？试试随机练习

  1. 先绑定 CF 账号并同步一次，减少抽到做过的题。抽题会排除本机已保存的提交和计时记录中出现过的题，包括归档账号的记录。
  2. 打开「随机练习」。只练一道时，选「每日一题」、难度档位，或设置难度范围和标签后点击「按条件抽一道」。
  3. 抽到题后，先看到难度；点击「开始做题」才会揭晓题目、打开 CF 并开始计时。原页面会继续显示用时。如果浏览器没有打开新标签页，点击「回到 Codeforces」。
  4. 使用绑定的账号提交，通过后等待结算。成绩会保存到「练习历史」，满足计分条件的成绩可参与 B50。

每日一题会根据已有成绩推荐难度；没有可计分成绩时，抽题范围为 800–2600，请留意抽到的难度。自定义抽题支持 800–3500，多选标签表示题目含有其中任意一个标签即可。

四题挑战：四道题共用 120 分钟

  • 每轮连续做四道题。各题用时单独记录，但挑战剩余时间共用。
  • 每次答案错误（WA）、超时（TLE）、超内存（MLE）或运行错误（RE），扣 10 分钟。编译错误（CE）和平台错误不扣。
  • 通过一题时，若剩余时间仍大于 0，且本轮此前从未耗尽时间，该题记为「可」（在挑战时间内通过），前三题各恢复最多 10 分钟，总余额不超过 120 分钟。第四题直接进入本轮结算，不再加时。
  • 结算期间暂停倒计时。关闭结算弹窗，准备好后点击「开始下一题」；恢复动画结束后才揭题并继续计时。同步和判题延迟不计入用时。
  • 四题全部记为「可」，本轮才合格。时间耗尽后仍可继续练习，但当前和后续题均记为「不可」，不再恢复时间，本轮不合格。已完成题目的实际成绩仍可参与 B50。
  • 进行中的挑战沿用开局时的规则；升级不会重算历史结算。

「随机挑战」也使用这套四题规则，难度覆盖 800–2600。小随机让各个难度被抽中的机会相同；大随机让每道题被抽中的机会相同，因此题量多的难度更常出现。更新前已经创建的轮次仍沿用创建时的规则。

6. 常见问题

账号保存了，为什么看不到做题记录？

先在「已绑定账号」确认平台和账号 ID 正确，再看同步是否完成。提示「待配置」时补充 Cookie；提示失败时按具体原因处理。只有近期记录时，尝试「回补历史」，并查看平台支持范围。首页「AC 记录」只显示已通过的题，失败提交可在练习数据中查看。

已经 AC 了，为什么 B50 仍是空的，或某道题没有上榜？

先确认是 Codeforces 题目，已经同步，并记录了有效用时。题目还需要 CF 官方难度；尚未评级时可以先记用时，公布评级并同步后才参与计分。辅助解题、未完成、已作废的记录不计分。有分也不一定上榜：旧题取前 35 道，新题取前 15 道，其他成绩在「全部成绩」查看。

今年做的题，为什么被放进旧题区？

新旧题看出题年份，不看你完成题目的日期。年度自动读取运行程序的电脑系统年份，无需选择。例如系统年份为 2026 年时，2026 年发布的是新题，2025 年及以前发布的是旧题。跨年后重新读取榜单，上年度新题自动归入旧题区，已有练习用时保留。

同步成功，但记录数比平台官网少怎么办？

先确认历史回补是否完成。公开范围、第三方镜像延迟、隐藏或已删除的记录，都可能造成差异；反复同步近期记录不能补齐平台不提供的历史。洛谷比赛中的临时题号不计入题目数量，但提交明细仍保留，因此也可能与平台展示的题数不同。

改名、换绑、取消关注和解绑有什么区别？
  • 同一账号改名：用于平台用户名变了、实际仍是同一个账号的情况。数字 ID 不能这样修改。
  • 换绑账号：新账号独立开始；旧账号归档，退出当前统计，历史保留。
  • 取消关注：只改变本机展示，不删除记录。
  • 解绑 / 删除用户：会删除对应的本地账号和提交数据，操作前请查看确认提示。
换电脑或更新项目，怎样保留数据？

数据存在本机，没有云端同步。更新前先备份，移动项目时保留数据库及自己的配置。具体步骤见项目 docs/local-install.md；不要把个人数据库、.env 登录配置或 data/cf-browser 浏览器登录资料公开分享。

按需设置：如何获取登录 Cookie？

Cookie 是网站用来识别登录状态的信息。洛谷、码蹄集同步需要它；力扣中国站回补本人历史也需要。其他普通公开记录可以跳过本节。

以下操作在电脑上完成。先在平台网站复制，再回到Algorithm DX填写；两个网站、不同浏览器之间的登录状态不会自动共用。下面的「标头」等名称以 Chrome / Edge 为例。

  1. 登录平台。在浏览器打开要同步的网站，登录自己的账号，进入个人信息或提交记录页。
  2. 打开网络面板。在平台网页空白处右键选「检查」，切到「网络 / Network」，然后刷新网页。
  3. 点开一条请求。在「名称 / Name」这一列中点击个人信息或提交记录相关的一行，不是点击列标题。
  4. 找到请求里的 Cookie。在详情中选择「标头 / Headers」，确认请求网址属于该平台。展开「请求标头 / Request Headers」，找到 Cookie；没有就换一条请求。
  5. 复制完整值。复制 Cookie 右侧全部内容，保留名称、等号和分号。不要带 Cookie: 前缀，也不要复制响应中的 Set-Cookie。
  6. 回本应用保存。新账号在添加表单中填写；已绑定账号在「账号管理」找到该账号，点击「设置登录」。粘贴到「登录 Cookie」框，点击「保存账号」，再查看同步结果。没有自动开始时，点击「同步最新数据」；力扣历史使用「回补历史」。

例如看到 Cookie: name=example_value; other=another_value，应只复制：

name=example_value; other=another_value

这只是格式示例，不能照抄。请复制浏览器里的实际完整值，不要只复制某一小段，也不要加引号或换行。有「复制值 / Copy value」菜单时可直接使用。

Cookie 相当于登录凭据，请只在本机输入框填写，不要发送到聊天、截图或共享文件。应用会保存在本机 .env 中，之后留空即可沿用；登录失效时再重新获取。

不知道选哪条请求，或找不到 Cookie？
  • 力扣中国站可找 leetcode.cn 下名称含 graphql 的请求；洛谷可找 www.luogu.com.cn 下路径含 /record/list 的请求；码蹄集可找 www.matiji.net 下路径含 /exam-back/ 的请求。这些是查找线索，以实际出现 Cookie 为准。
  • 只看到「名称、状态、类型」：先点一条具体请求，详情中才会出现「标头」。面板太窄时拉宽它，或点击标签旁的「≫」。
  • 列表为空：清空筛选、选择「全部」、恢复录制后刷新。打开工具之前的请求不会自动补录。
  • 只有「临时标头 / Provisional headers」：等待请求完成，或换一条已发出的请求；必要时勾选「停用缓存 / Disable cache」再刷新，不必清除登录 Cookie。
  • 只有 Set-Cookie：当前看的是「响应标头」，请回到「请求标头」。
保存 Cookie 后仍然失败？
  • 格式错误：检查是否混入前缀、引号、换行或整段请求，重新复制完整字段值。
  • 登录失效：在平台重新登录并复制新 Cookie；只刷新本应用不会更新登录信息。
  • 账号不匹配：核对浏览器登录账号与绑定的 ID，不要只比较昵称。力扣不能用自己的 Cookie 回补他人的历史。
  • 403、访问受限或格式变化：先确认平台网页能正常访问。新 Cookie 仍失败时，可能是平台限制或接口变化，请保留具体报错用于反馈。

浏览器工具参考：Chrome 网络面板、Edge 网络面板、Firefox 请求详情。

洛谷：填 UID 后，还要设置登录

数字 UID 用来找到账号；你自己的 Cookie 用来读取提交。只填 UID 能绑定账号，但还不能同步记录。已有有效 Cookie 时，添加其他洛谷账号只填 UID 即可；所有关注的洛谷账号共用这一份配置，无需好友的 Cookie。

「同步最新数据」默认读取最近 100 条提交，更早的记录请用「回补历史」。会保存题目、时间、判题结果等平台提供的字段，不读取源代码或逐测试点详情。私有、比赛隐藏或当前登录账号无权查看的记录可能读不到。

前往账号管理 · 获取 Cookie

牛客：只需数字 ID

选择「牛客」，填写个人主页 /users/ 或竞赛主页 /profile/ 后面的数字 ID，然后保存并同步，无需 Cookie。本人和题友都可以添加。

同步的是牛客竞赛站「TA 的练习 → 编程题」中的公开记录，支持历史回补，不含选择题和非公开记录。记录可进入 AC 记录和练习数据统计，但不参与 B50；页面无法访问时会显示失败并保留已有数据。

码蹄集：先用 Cookie 识别自己的账号

  1. 在「账号管理」选择归属用户和「码蹄集」。绑定自己时，账号栏可以留空；也可以填自己的昵称或个人主页链接。
  2. 首次使用时粘贴自己的 Cookie。已保存且未过期时可留空沿用。
  3. 点击「保存账号」，应用会识别数字 ID 并开始近期同步。也可先点「识别我的账号」核对身份，再保存。昵称与登录账号不一致时不会绑定。
  4. 需要更早的记录时，再点击「回补历史」。自己的 /personalcenter/homepage 地址通常不含 ID，无需从中找数字。

绑定他人时，请填对方的数字 ID 或含 /other-homepage/ 的主页链接，仍然使用你自己的 Cookie。所有码蹄集账号共用登录配置，过期后更新一次即可。

已有 JSON 记录文件？查看备用导入方法

日常使用上面的同步方式即可。文件导入适用于你已经有真实提交记录文件的情况；下载的空模板不包含成绩。

  1. 先绑定码蹄集账号，在账号旁点击「导入记录」。
  2. 选择 JSON 文件，核对账号、提交数量和预览，再点击「确认导入」。无需放到指定目录或修改配置文件。
  3. 文件中的 account_handle 必须等于绑定的数字 ID。每条记录需要提交 ID、题目 ID、判题结果和提交时间；时间为 Unix 时间戳（秒或毫秒）。不要放 Cookie、密码或源码。
{
  "account_handle": "网站账号ID",
  "records": [{
    "submissionId": "真实提交ID",
    "problemId": "真实题目ID",
    "problemTitle": "题目标题",
    "judgeResultSlug": "Accepted",
    "submitTime": 1700000000,
    "languageName": "C++"
  }]
}

以上只是格式示例，不能当作真实成绩导入。每个文件最多 10 MB、100000 条记录；确认后导入整份文件，不受近期同步默认 100 条的限制。重复提交会合并，格式或账号不匹配时整批拒绝。

CF 自建比赛：只有需要群组记录时才设置

如果只同步普通公开 CF 记录，可以跳过本节。群组（Group）比赛需要额外设置，而且你登录的 CF 账号必须能查看该比赛的 Status（提交记录）页面；仅能看榜单还不够。

先绑定要统计的 CF 账号，再到「账号管理」顶部的「CF 自建比赛」选择该账号，点击「配置自建比赛」。下面所有操作都从这个窗口开始。

推荐：在日常使用的 Edge 中安装扩展

  1. 在 Edge 地址栏输入 edge://extensions，打开「开发人员模式」，点击「加载解压缩的扩展」，选择项目中的 extensions/cf-sync 文件夹（里面有 manifest.json）。
  2. 在同一个 Edge 中登录 Codeforces，确认能打开需要读取的群组和提交页。安装扩展后刷新 CF 标签页。
  3. 回到应用的配置窗口，获取方式选择「普通 Edge 扩展（推荐）」，粘贴自己的群组链接，每行一个。群组链接可包含 /contests，也支持单场比赛链接。点击「生成连接码」并复制。
  4. 点击 Edge 工具栏里的 Algorithm DX 扩展图标，填写本机面板地址（默认 http://127.0.0.1:8787，改过端口就填实际地址），粘贴连接码，点击「连接」。
  5. 回到应用，确认显示「扩展已连接」，点击「保存并获取群组历史」。保持 Edge 和已登录的 CF 标签页开启，等待同步结果。应用页面可以在其他浏览器中打开。

「已连接」表示扩展连上了应用，记录是否读到要看随后的同步结果。连接码只用于连接本机面板，不是 CF 密码或 API Key。重新生成会让旧码失效。

扩展断开、出现安全验证，或某场比赛读取失败
  • 出现安全验证时，点击扩展的「打开读取页面」，手动完成验证后回应用重试。扩展不会自动处理验证码。
  • 更新扩展后，在 edge://extensions 重新加载，再刷新原有 CF 标签页。确认扩展有权在 codeforces.com 运行。
  • 重启应用、关闭浏览器或退出登录后，连接可能需要数十秒恢复；也可在扩展中点击「连接」。
  • 若提交页手动打开也回到群组列表，先确认该场比赛的访问权限。应用会保留其他比赛的数据，将无法读取的比赛标记为未完成，不会当作零提交。

扩展读取已配置群组的比赛和提交页面，通过自己的后台标签页翻页，只把数据发送到配对的本机应用，不读取 Cookie、密码或源码。扩展同步需要通过应用页面启动。

其他方式：专用浏览器（兼容方式）
  1. 在配置窗口填写群组或比赛链接，获取方式选「专用浏览器（兼容方式）」，点击「打开 CF 登录窗口」。
  2. 在新开的独立窗口登录 CF。这个窗口与平时浏览器的登录状态不共用。确认能查看比赛的 Status 页面，遇到验证时手动完成。
  3. 回应用点击「保存配置」，再「同步最新数据」或「回补历史」。同步期间保持专用窗口开启，可以最小化。

登录状态保存在本机，下次打开可继续使用，过期后重新登录。若普通 Edge 能访问而专用窗口一直验证失败，请使用上面的扩展方式。

此方式需要电脑有图形桌面及 Edge / Chrome / Chromium。Windows 会自动查找 Edge；其他安装位置可在 .env 的 ALGORITHM_DX_CF_BROWSER_EXECUTABLE 中指定。登录资料保存在 data/cf-browser，请勿分享。

其他方式：API Key（适合已确认 API 有权限的账号）
  1. 使用有比赛访问权限的 CF 账号，打开 CF API 设置，在「API keys」区域取得配套的 key 和 secret。
  2. 在应用配置窗口中选择「API Key」，填写群组或比赛链接，将两项分别粘贴到「API Key」和「API Secret」，点击「保存配置」。
  3. 点击「同步最新数据」检查授权是否可用；更早的提交使用「回补历史」。保存成功本身不代表已经取得比赛记录。

看到「Create OAuth App / Edit OAuth App」、Client id、Client secret 或 Redirect Uris 时，你打开的是另一种授权设置。应用目前不支持 OAuth，不要把这些值填入 API Key / Secret，也无需配置回调地址。

更新授权时两项一起填；以后留空可沿用。授权保存在本机 .env，各 CF 账号共用。API 方式不会使用浏览器登录状态；网页能打开不保证 API 能读取提交。

若提示找不到比赛，先核对链接中的比赛编号、密钥配对及电脑时间。编号正确仍失败时，可能是 API 权限限制，可改用扩展方式或联系群组管理员确认访问权限，不必反复创建密钥。授权原理见 CF API 授权说明。

群组中新增的可访问比赛会在后续同步时自动发现。想停止群组同步，清空比赛链接并保存即可，已有记录会保留。群组题目需要配对到有官方难度的原题，才可能参与 B50，方法见下一节。

群组题没有难度？检查原题配对

「原题」指被搬进群组比赛的那道 CF 或 Gym 题。应用会尝试查找同名题和题面中的原题链接，再核对题面、约束和全部样例；仅标题相同不会直接赋予难度。请使用 0.6.0 或更新版本的扩展。

  1. 同步群组记录后，打开「账号管理 → CF 自建比赛 → 配置自建比赛」，展开「原题配对与难度」。
  2. 找到对应题目，查看匹配结果。知道原题链接时，将它粘贴到「原题链接」，点击「自动核对链接」。
  3. 翻译或改写后的题目可能无法自动确认。请打开两侧题面自行核对，确认无误后勾选「我已打开两道题，确认是同一道题」，再点击「确认原题」。
  • 待补充原题链接：尚未找到原题，可以手动提供链接。
  • 需要确认原题：尚不能确定是否同题，请核对题面。
  • 核对未完成：读取遇到问题，可稍后重试；已有确认结果会保留。
  • 原题未评级：原题已找到，但 CF 没有提供题目难度。个人 Rating、比赛积分和 Gym 整场难度不能替代题目难度。

确认是同一原题的记录，在 B50 中只占一格，取最佳成绩；各次 AC 和练习历史仍分别保留。新旧题按原题的出题年份划分，不用群组开赛日期代替。群组比赛时间用于估算比赛用时，你填写的实际用时和提交时间仍保留。

B50 评分：先分清三个数字

  • 题目难度（题目 Rating）：CF 标注的题目难度，如 1400；不是你的 CF 个人 Rating。
  • 达成率（也称完成度）：本应用根据难度和用时计算的表现指标。它不是测试点通过比例，已 AC 的题也可能显示低于 100%。同一难度下，用时越短，达成率越高。
  • 单题得分与 DX Rating：难度和达成率共同决定单题得分；B50 中所有单题得分相加，就是 DX Rating。这是本项目的娱乐向指标，不是 CF 官方 Rating。

B50 分为旧题前 35 道（B35）和新题前 15 道（B15），不足时可以空着。以选择 2026 年为例：2026 年发布的题进入新题候选，之前发布的进入旧题候选，之后发布的题不参与；每题取当前保存的最佳有效成绩。

没有用时或没有官方难度的题暂不计分。题目评级公布后，同步即可重新参与排名；是否上榜还要比较同区其他题的得分。未知出题日期暂按旧题处理，不同平台的同一道题目前不能可靠合并。

想知道某个难度要做多快？在「DX Rating」顶部点击「参考表」，可以查看各难度获得 S、SS、SSS 等评级的参考用时。

想看计算过程：参考用时、公式和系数

T97是模型给某个难度设定的参考用时。用时等于它时，达成率为 97%（S）；它不是每一道具体题目的实测平均时间。例如某难度的参考用时若为 30 分钟，实际用了 30 分钟，就对应 97%。

单题得分 =（题目难度 ÷ 计分除数）× 计分系数。各题四舍五入到一位小数后，再相加得到总分。当前参数由下面实时读取。
