# 成就、收藏品与 Tracker

## 数据边界

- 玩家档案、解锁记录与当前装扮只保存在本机 SQLite。
- Codeforces 比赛题单来自已有的官方 `problemset.problems` 缓存；目前只统计带官方 Rating 的公开题目。
- AtCoder Tracker 使用项目同步时缓存的 AtCoder Problems 公开目录（`contests.json`、`problems.json` 与难度模型；题目记录自带所属比赛 ID）。AtCoder Problems 是非官方服务，页面会在缓存未准备好时明确提示先同步。
- 本地界面测试内置一组真实的 LXNS 图片样例：icon 11、plate 11、frame 11。下载地址和用途记录在 `public/assets/collectibles/SOURCES.md`；第三方图片的来源记录不等于获得新的再分发许可，发布前仍需按上游要求确认使用范围。

## 收藏品模型

`user_collectibles` 保存已经获得的物品快照，类型包括：成就、称号、预设头像、头像框、背景板、姓名框和 B50 背景。`user_profile_loadouts` 保存每个槽位当前装备。默认个人卡片被定义为一整套始终可用的“新手装扮”。

头像可在四种来源间切换：已解锁的预设头像、绑定账号的 Codeforces 头像、绑定账号的 AtCoder 头像、自定义上传图片。AtCoder 头像从公开个人页读取，并在不可用时回退到官方默认头像。上传图片在浏览器端居中裁成 256×256 WebP 后再保存到本地数据库；展示区本身保持纯展示，所有切换操作只出现在装扮弹窗里。

四题段位挑战首次合格会解锁使用舞萌「真初段 合格」素材的段位姓名框。玩家信息区会扫描本地已通过的段位历史，将最高段位对应的舞萌 course-rank 徽记显示在用户名白条最右侧；用户名与徽记共用同一个白底，称号保持在下一行。随机段位使用真伝／裏皆伝标记，普通四档依次映射为初段、五段、十段、真皆伝。

所有页面共用收藏品解锁通知：未确认的新物品会在右下角依次显示名称、稀有度、说明与获取条件，可收下或立即装备；确认状态保存在 SQLite，切换页面和刷新不会重复丢失。装扮弹窗只列出玩家已经获得的物品，并提供名称／说明搜索、类别筛选和稀有度筛选，避免未获得的比赛称号把列表撑满。

静态成就按本地记录自动补发，比赛称号是动态物品：名称取比赛名，来源元数据保存比赛 ID 与判定规则。已发放的物品不因平台重判或目录变化自动回收。

### Codeforces 比赛称号

只有在该账号历史回补完成、且本地全量题库能确认题单时才判定，避免近期同步或不完整历史误发奖励。

- 白色称号：该场每一道带官方 Rating 的题都至少有一次 AC。
- 银色称号：满足白色称号，并且每道题按提交时间排序的第一次提交就是 AC，即全部题目均为 Clean Solve。

## 指定题目练习

随机练习页允许输入 CF / AtCoder 题号或官方题目链接。服务端完成以下检查后才创建练习：

1. 题号格式正确，且题目存在于当前可计时题库；
2. 当前用户所有账号（包括归档账号）没有该题提交；
3. 没有该题的既有计时记录；
4. 当前用户没有另一场正在进行的练习。

校验通过后浏览器立即打开题目并启动原有计时器；计时、同步 AC、结算与 B50 计分仍共用同一条链路。

## Tracker

`/tracker.html` 按比赛一行、题目一格显示本机进度：

- 绿色：已经 AC；
- 黄色：有提交但尚未 AC；
- 空白：没有提交；
- 星标：第一次提交就是 AC（Clean Solve）；
- 整行绿色：完成比赛；整行均带 Clean Solve 时显示银色完成标记。

Tracker 只读本地题目目录和提交记录，支持 Codeforces / AtCoder、用户切换、比赛搜索与分页。它与比赛称号共享同一套状态定义，但 Tracker 可以在历史未完整时展示当前进度；发放称号仍使用更严格的完整性门槛。

## B50 视觉与导出

个人页上屏按舞萌玩家信息区的层级组织：左侧头像，右侧姓名框内依次放 Rating、玩家名、称号和平台标识；下方独立区域展示总过题数、最近过题及各平台统计，不在上屏里放任何按钮。装备的称号、B50 背景会进入本地导出图。导出卡片直接复用仓库内 `gam-rank-*.png` 的 S / SS / SSS 徽章；页面主题复用已有结算底板与 Prism 背景纹理。新增资源包时应保留来源、作者、许可和适用范围，不能只记录下载地址。
