# Algorithm DX：首轮问题清单

日期：2026-09-22。范围：现有代码、现有测试、内存数据库及合成数据最小复现。
首轮仅调整品牌和项目定位；随后经用户同意修复第 1 项。随后经用户同意一并修复第 2–5 项。
首轮基线：84 项测试通过。第 1 项修复后：89 项通过，包含新增身份隔离回归测试及 CLI 换绑测试。

## 1. P1：改账号标识混入另一个人的历史

位置：src/account-admin.ts:242；src/db/database.ts:80。
账号已有提交且历史回补已完成时，将 old_handle 改成 different_person，只更新 handle/handle_key；旧提交、history_cursor 和 history_complete 原样保留。
已复现：新 handle 下仍有旧提交，cursor=501，history_complete=1。继续抓取会混入新账号的数据；历史回补也可能因为“已完成”被跳过。
建议讨论：区分“同一平台账号实际改名”和“换绑另一个账号”；后者创建独立账号，不能沿用原历史与进度。真实改名也需要验证身份或明确操作类型。
状态：已修复。界面区分同一账号改名与换绑；改名要求身份确认，数字 ID 禁止改名；换绑将旧账号及其独有用时归档，新账号从空记录开始；统计、B50、同步排除归档账号，同步进行中禁止身份修改。归档记录保留在数据库，管理界面可查看数量，暂未提供恢复入口。

## 2. P1：失败的绑定操作仍覆盖登录凭据

位置：src/account-admin.ts:162–177。
bindAccount 在检查账号重复及归属之前，先调用 upsertEnvVar。尝试将已属于用户 A 的洛谷账号绑定给用户 B 时，虽然返回 ACCOUNT_OWNED_BY_OTHER，平台共享 Cookie 已被替换。
复现使用临时 .env 和虚构凭据：绑定被拒绝，但文件发生改变。未接触真实 .env。
影响：一次失败操作可让其他同平台账号的后续同步失效。
建议讨论：所有可预先完成的账号和归属校验必须先于凭据落盘；明确处理数据库写入失败时的文件回滚。
状态：已修复，见下方本轮修复记录。

## 3. P2：填写后未进 B50 的题没有管理入口

位置：src/dx/rating.ts:365、453；public/dx.js:318–339。
scoreProblem 排除无评级的题；buildPending 排除已经填写用时的题；页面可编辑题目主要来自 B50 格子和待填写列表。
已复现：一题已 AC、已填用时、评级为空，board.total=0 且 pending.length=0。数据没丢，但这页无法再找到它编辑或清除。已评分却落在 B35/B15 截断之外的题也应纳入统一管理。
附带错误：此时空状态会提示“所有填过用时的题都超出榜位上限”，真正原因可能是缺评级。
建议讨论：增加独立的“全部已解题 / 用时记录”管理列表，B50 仅作为展示结果，不承担唯一编辑入口。
状态：已修复，见下方本轮修复记录。

## 4. P2：选择旧年度仍计入之后出题的题目

位置：src/server/api.ts:424–444；src/dx/rating.ts:422。
年度只传入起始时间，isCurrent 只判断 releasedAt >= 年初，没有年末上界；查询也没有限制 AC 时间。
已复现：选择 2025 年，2026 年发布并 AC 的题仍占据该年的 B15。
建议先确定：年度选择是“当年历史榜单”还是“自该年起的新题分组”。若为历史榜，还必须处理用时覆盖后如何保留历史成绩；目前每题仅保存一个可覆盖用时，没有年度快照。
状态：已修复。年度作为出题年份分区，使用当前保存用时，不提供历史快照。

## 5. P2：DX 页说明与实际计分不一致

位置：public/dx.html:90；src/dx/rating.ts:factorFromAchievement。
页面页脚称 SSS+ 系数为 1.160，实际函数 factorFromAchievement(100.5)=1.256659793814433（约 1.257）。
此外 HTML 直接显示 Markdown 的 **出题日期**，不会产生预期加粗。
建议讨论：以服务端规则元数据生成说明，消除前端硬编码的第二套数值；本轮不改变评分公式。
状态：已修复，见下方本轮修复记录。

## 产品范围缺口，不直接当作程序 Bug

- 全平台记录与全平台 B50 是两回事：当前 DX_PLATFORM 固定 codeforces，跨平台难度和用时标尺尚未定义。
- 平台支持不等于完整历史：力扣中国站为近期 AC，码蹄集为本地导入。
- 比赛提交间隔只能作为用时估计，不能证明实际连续思考时间；手填实际用时与估计用时是否应区分来源，需要确定。
- 面向 GitHub 发布：当前目录没有 Git 仓库和 LICENSE 文件。许可选择、发布内容范围、研究数据是否一起发布，另行确认；本轮不创建仓库或发布。
